## Area 1: bounded CROMA export

Ravi's `features.py:extract_features` verifies the preprocessing manifest, ordered batch offsets, paired IDs and input file hashes; it loads one prepared batch, invokes CROMA in mini-batches, writes a batch feature file, reloads it for equality, and publishes the whole output only after success. Its `extract_croma.py` exposes `--batch-size`. A failed run removes the temporary tree; it does **not** resume completed feature batches inside that run. The feature tests exercise ordering, hash rejection, wrong profiles, and source-manifest mutation.

SatQuery's original `run_pipeline3_5000_baseline.py:build_features` processes the frozen manifest in configurable shards (historically 32, producing 157 shards), with configurable CROMA inference batches. The current Phase 2D.2 path reuses that cache and verifies each source shard hash, ordered IDs/splits, shape, dtype, and finiteness. It creates hybrid shards atomically, reuses only validated outputs, and emits 15,000 unique per-image representation receipts plus 157 shard receipts. `load_verified_receipts` rechecks artifact and sample hashes; `representation_catalog.py` admits only verified rows. `test_representation_materialization.py` covers resume, checksum, order, split, interrupted outputs, receipt tampering, and duplicate identities.

**Observed legacy caveat:** the original `build_features` shortcut checks only `area_ids` before reusing a preexisting NPZ during *new feature extraction*. Its completed cache loader, materializer, and catalog perform stronger verification. Do not interpret the shortcut alone as a full provenance check. The frozen cache has already passed downstream validation; no new extraction is requested. If extraction is reopened for a new population, require a pinned per-shard source/checkpoint/config receipt before reuse. Ravi's exporter does not provide this missing receipt, so copying it does not resolve the caveat. No modification to the historical builder is justified in this task.

## Area 2: selective acquisition

Ravi's `remote_lmdb.py` reads selected keys from a pinned LMDB using strict range responses with five retries; `download_bigearthnet.py` resumes partial source-cache files, verifies pinned SHA-256 digests, performs a seeded country-balanced selection, fetches only selected S1/S2 values and reference maps, validates native bands, then makes verified 100-area ZIP shards. Completed ZIPs are skipped after hash/selection checks; an interrupted shard is repeated. `test_download.py` covers strict range handling, partial cache, selection, reconstruction, and resume. The Colab notebook calls this path; it is not a separate downloader.

SatQuery's `acquire_pipeline3_5000_s2.py` already carries the narrow strict range/LMDB pattern. It takes identities solely from the frozen 5,000-area manifest, reads only missing optical records, retries bounded ranges, validates band sets/shapes/dtypes, round-trips each GeoTIFF, writes an atomic per-area receipt, and verifies completed areas on resume. `audit_pipeline3_5000_s2_acquisition.py` checks the selected population, band hashes, unmatched files, and provenance. This is a smaller and finer-grained recovery unit than Ravi's ZIP shard. There is no demonstrated current need for a generic RSVQA/VRSBench/CDVQA downloader: their authoritative source formats, integrity metadata, licenses, and selection contracts have not been established here. Build a source-specific adapter when such an acquisition is approved, while reusing SatQuery's manifest/receipt principles.

## Area 3: evaluation scaffolding

Ravi's `evaluation.py` loads verified feature/target batches, rejects duplicated S1 identities, retains official area splits, predicts in batches, computes token-weighted class/aggregate coverage metrics, and bootstraps by whole image area. `prediction_data.py` and `predict_cover.py` retain feature, checkpoint, class-order, and ordered output contracts. `tests/test_evaluation.py` exercises alignment and bootstrap behavior. Its recorded `reports/pipeline-1000/evaluation/test-report.json` and `reliability.json` bind checkpoint and input-manifest hashes. These are 1,000-area results and are not comparable replacements for SatQuery's 5,000-area baseline.

SatQuery's `phase1_foundation.py:coverage_metrics` already computes whole-area bootstrap intervals and per-class/aggregate metrics. The frozen Pipeline 3 flow has held-out area-level evaluation, saved ordered predictions, exact checkpoint and cache hashes, and split/dataset fingerprints. The Phase 6R.2B revalidation stores all 5,000 predictions and verifies shard hashes; `finalize_pipeline3_5000_6r2b.py` recomputes reported metrics from saved predictions and targets and writes a reproducibility fingerprint. `tests/test_pipeline3_5000_audit.py` protects the dataset, split, metrics, and scientific fingerprint. `evaluate_landcover.py` is an earlier separate classifier utility and is not the authority for the current hybrid coverage baseline. A new `EvaluationRun`/`MetricSet` framework would duplicate these existing layers without a present consumer.

## Integration decision and rejected changes

No production code or new tests were added. There is no Ravi capability missing from the **current** bounded materialization, selective BigEarthNet acquisition, or sealed coverage evaluation path that materially improves reproducibility or recovery. Specifically rejected: copying Ravi's fresh-directory feature exporter, introducing 100-area ZIPs, creating a generic dataset downloader without a validated source, importing the 1,000-area evaluation stack, and adding an abstract evaluation object graph. The legacy cache-reuse caveat is recorded above for any future new extraction, with its specific required receipt check.

Priority #1 BigEarthNet.txt spatial semantics remains `UNRESOLVED / FAIL-CLOSED`; this audit makes no spatial mapping claim.
